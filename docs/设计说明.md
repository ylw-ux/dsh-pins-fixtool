# dsh-pins — 把对话里的段落固定到右侧栏

在 DeepSeek Harness 的对话界面里**划选一段文字**，浮出来的动作条里点「固定」，这段内容就会进入**右侧栏**的固定片段列表：像便签一样每屏排 8-10 条，点击任意一条可以跳回原文并高亮。

解决的是这个场景：让模型解读长文档/论文代码时，回复很长甚至跨多轮，来回滚动找上下文会打断思路——把关键结点固定下来，就等于给这段对话建了一份"上下文骨架"。

## 怎么用

| 操作 | 效果 |
|---|---|
| 划选文字 | 选区上方浮出动作条：**固定 / 标签 / 固定并引用 / 引用 / 复制**——五个动作一眼都在，不用先展开标签框 |
| 动作条上的「标签」 | 就地展开一个标签输入框；**其余按钮照常可点** |
| 写了标签后点「固定」或「固定并引用」 | 固定（并可引用）**并打上这个标签** |
| 输入框**空着**就点其它按钮 | 按那个按钮本来的意思执行（只固定 / 只引用），**不报错**——空标签没有意义，可能只是点开了或忘了填 |
| 输入框里回车 | 固定并打标签（与上面一致） |
| `Alt` + `P` | 固定 / 取消固定当前选区（等同于点动作条） |
| 同上再划选同一段 | 该段已固定时，第一个按钮变成「取消」 |
| 动作条上的「引用」 | 把这段作为**自带出处的引用块**放进输入框（不固定；发送后内容就随消息一起存在，不需要任何缓存） |
| 输入框里打 `@`，选「固定片段」 | 它在 `@` 菜单的**第一行**；进入本对话的固定片段列表，**顶部那条写着「固定片段 · N 条」**（筛选中会补上「命中 M」），点它能退回上一层。列表顺序就是你在面板里选的排序，列表里再打字就是搜索，回车或鼠标点一下即插入一个**引用芯片** |
| `@固定片段/` 后面继续打字 | 和上一行是同一层——这个词和内容、标签都比对，命中的片段留下来 |
| 点输入框里的引用芯片 | 打开右侧栏，并让**那条卡片脉冲高亮**（和官方 `@文件` 芯片点开预览是同一条路） |
| 芯片所指的固定片段被删了 | **照常发送**：芯片自己带着引用全文；删除只影响"点开回看"，不会拦你的消息 |
| 鼠标停在卡片上 | 约 0.12 秒后**卡片原地展开**（上限 `min(60cqh, 420px)`），可在卡片内滚动看全文 |
| 点卡片正文 | **永远 = 跳回原文**（无论展开与否），落到选中的那段文字并居中；末尾的片段贴底（「全部」里别的对话的卡片例外，见下） |
| 点卡片其它位置（meta 行、四周留白） | 展开态下切换标签编辑区；折叠态下跳回原文 |
| 卡片上的 `#` | 切换标签编辑区（展开态下常驻可见）：胶囊行 + **独占一行的输入框** + 可折叠的「管理这个片段的标签」 |
| 卡片上的 `❞` / `⧉` / `✕` | 引用到输入框 / 复制原文（保留换行）/ 取消固定——**「全部」里的卡片一样有这四个** |
| 面板顶部「本对话 / 全部」 | **两个视图各管一件事**：本对话只管这一段对话；全部管所有对话 |
| 面板顶部「⌃ 全部收起 / ⌄ 全部展开」 | 只在「全部」且会话多于一个时出现，一次折叠所有会话分组 |
| 「全部」里的会话分组头 | 点 `▾/▸` 折叠该会话的片段；分组头显示会话真名与条数 |
| 面板顶部「⇅ 排序」 | 点一下换一种：**原文 ↑ / 原文 ↓ / 时间 ↓ / 时间 ↑**，两个视图都生效、选择被记住 |
| 面板顶部「⤓ 导出」 | 把**当前视图**（含搜索与标签筛选）导出成 markdown 提纲 |
| 搜索框 | 匹配固定内容和标签；在「全部」里**也匹配会话名**（带清除键，Esc 也可清） |
| 会话名命中 | 出现在「全部」列表顶部的虚线框里，带 `会话名` 小标；**点它只在面板里跳到该会话分组并高亮，绝不会切换你当前所在的会话** |
| 筛选胶囊 | 点选筛选，**可多选叠加**（命中任一已选标签）；选中为实心，旁边有「清除筛选 (N)」 |
| 可折叠的「管理…标签」 | 一行一个标签、**完整显示标签名**、带使用次数与垃圾桶；有高度上限、内部可滚动、下沿可拖动改高度 |

右侧栏是 Harness 的标准右栏标签：第一次固定会自动把右栏展开，之后它就是「固定片段」这一个页签，可以和文件树、文档并排分屏；切走再切回**不会丢**搜索词、筛选与滚动位置。右栏关掉后，从左栏底部的入口（Settings 旁边、带条数角标）随时打开。

## 两个视图各管一件事

早期版本让「本对话」也搜到别的会话名，结果是个自相矛盾的中间态：**名字能看见、内容看不见**——既然点进去要跳到「全部」，那这个名字从一开始就该属于「全部」。现在：

| 视图 | 管什么 | 搜索范围 |
|---|---|---|
| **本对话** | 只这一段对话的片段 | 片段正文、标签 |
| **全部** | 所有对话，按会话分组 | 片段正文、标签、**会话名** |

**两个视图各留一份筛选。** 搜索词和标签筛选曾经是一对共享状态，于是在「全部」里选中一个标签会顺手把「本对话」也筛了——而标签胶囊列表本来就是按视图分范围的，本对话只列本对话出现过的标签，**从「全部」带过来的那个标签在这里可能根本不存在**：列表空了，原因却在另一个屏幕上。功能两边一样，范围各归各的。

**排序不在此列**：它是全局偏好，两个视图共用并且持久化——它回答的是"你想怎么看"，不是"你在看哪一段"。

会话名命中在「全部」里单独用虚线框标出并带 `会话名` 小标，点击**只在面板里滚动定位 + 高亮**，不会动你正在读的那个对话——用户点它往往只是想在那儿固定一条或改个标签。

**「全部」里的卡片是完整公民**：`#` 加标签、`❞` 引用、`⧉` 复制、`✕` 取消固定，四件都能做，而且都**指向那张卡片自己的对话**（引用会把它放进你当前这个输入框，出处行写的是它原来那个对话；标签也是改它自己那条）。

**唯一不行的是"跳回原文"**：别的对话的消息根本不在当前 DOM 里，点了只会说明这一点，**不会替你切换对话**。

> 这里修过一个反向的坑：早先「全部」的卡片被写成"只读"，做法是给它们一个永远返回 `false` 的改标签函数。但标签编辑区**照样会被点开**——于是加标签会弹出「已经有 #x 这个标签了」（一条它从来没有过的标签），删标签也毫无反应。**一个能打开却会撒谎的控件，比一个不存在的控件更糟。**

## 关于"引用"的设计取舍

引用有两种形态，**都自带内容、都不是指针**：

| 形态 | 怎么来 | 输入框里长什么样 | 发送时 |
|---|---|---|---|
| **引用块** | 浮条 / 卡片上的「引用」 | 直接是一段带出处的 markdown 引用 | 就是那段文字 |
| **引用芯片** | 输入框打 `@` → 「固定片段」→ 选一条 | 一个小芯片（`固定 · 摘录…`） | 发送前由本插件的 codec 换成那段引用 |

两种形态的原文都进消息，所以：模型**真的看得到**这段内容（一个指向缓存的"〔引用1〕"标记，模型只会看到那几个字）；发送后**永不过期**——没有 TTL、没有缓存清理、没有"过一段时间点开发现打不开"的静默腐化；出处写在引用行（会话名 · 第几轮 · 来源 · 代码语言）。

### 芯片：之前那段判断是错的，这里更正

这一节早先写的是"草稿在宿主里是纯文本，第三方插件造的 chip 名在发送时不会被展开，所以完整版做不了"。**这个判断是错的。**

宿主有一条公开的引用通道 `ctx.inputTriggers.registerSource()`（官方 `@文件`、`@会话` 走的就是它），引用源可以带一个 `ReferenceCodec`：

- `serialize(ref, signal)` —— **发送前**由本插件的代码把芯片换成模型该读的文本，逐个芯片调用；
- `clipboardText(ref)` —— 剪贴板投影。

而且契约很硬：**序列化失败就拒绝这次发送、还原草稿，不许静默降级成芯片名**。

### 由此定下来的两个决定

**1. 芯片的内容存在自己身上，不存 id。** `ref` 的载荷是 `<pinId>\n<引用全文>`。

因为 codec 一旦"查不到"就是拒绝发送，而拒绝发送是插件最不该做的事。把全文塞进 `ref` 之后**不存在查不到的情况**：删掉那条固定片段、清空存储、刷新页面，发出去的字都不变。代价是 `ref` 和正文一样长——它只活在编辑器节点里，不落盘、不显示。

**2. 芯片的剪贴板形态 = 它的展开形态。**

草稿是**持久化**的（`dsh.conversation`），写进去的是**剪贴板投影**：刷新页面或切走再切回，芯片会退化成纯文本。所以让 `clipboardText` 与 `serialize` 返回**同一个字符串**——退化之后与展开之后逐字节相同，用户看不出区别。这一条是设计出来的，不是补丁。

代价老实说：草稿底下的文本会变长（芯片完好时你看不见；全选复制会连引用一起复制——但这正是"引用"该有的意思）。

### 故意不做的三件

- **不做 `lexicon` 装饰**：它能让退化成纯文本的 `@名字` 看起来仍像芯片——**看起来对、发出去是错的**。宁可让它一眼看出变成了纯文本。
- **不做 `/` 触发**：`/` 是命令通道（行首限定、走 claim 与 `matchEnter` 判定、claim 之后还会被压制），`@` 才是引用通道。
- **不做多选**：宿主的 pick 是单次结算，一次只带一个芯片进来。要引三条就打三次 `@`。

### 点击芯片会做什么

单击芯片走的是官方 `@文件` 芯片"点开预览"的同一条路：**打开右侧栏 + 那条卡片脉冲高亮**。若那条固定片段已经被删掉，消息里仍然有它的原文——插件只会说明这一点，**不会拦你发送**。

## 设计要点

- **一条消息可以固定很多段**：去重按「消息 + 文本」判断，不是按消息——同一段回复里可以固定多个结点，这正是长回复拆提纲需要的。给某一段加标签时，命中的是**离选区最近的那条**，所以一条消息里的第 3 段不会被第 1 段顶掉。
- **四种排序**：**原文 ↑/↓**（按轮次 → 消息在轮内的位置 → 段内偏移；新固定自动落到它在对话里的位置，不需要"插入规则"）与**时间 ↓/↑**（按固定时刻）。面板只有「⇅」一个按钮循环切换，选择持久化。
- **引用的原文进消息，不是指针**：见上一节。
- **hover 展开的四个约束**：展开上限挂在**卡片整体**（内窗只吃掉剩余空间）；上限用**容器查询单位**而不是 `vh`（右栏常比窗口矮）；内窗右侧留一条 **16px 边带**，滚轮落在边带上仍然滚列表（用 `margin` 而不是 `padding`——padding 属于滚动盒，滚轮会继续滚文字）；列表滚动时与停止后 150ms 内**不响应 hover**，否则滚列表时卡片会在指针下乱弹。
- **编辑是粘性的**：点进标签编辑区后，鼠标移开不会收起——正在输标签时输入框消失是已经咬过一次的坑。同时同一时刻只展开一张卡。
- **跳转与编辑各有各的入口，不靠状态猜**：卡片会 hover 展开，所以"折叠态点击 = 跳回、展开态点击 = 编辑"这条规则在真机上等于取消了跳转。现在**点正文永远是跳回**，编辑区只由 `#` 按钮（展开态常驻）和卡片非正文区域切换。
- **标签的增与删是两件事**：输入框只负责**添加**（重复添加会提示"已经有了"，不会反而删掉）；删除只走胶囊与垃圾桶。一个既能加又能删的输入框是无法预期的。
- **删除标签有三层入口**：片段卡片里的胶囊；卡片内可折叠的「管理这个片段的标签」；面板顶部的「管理本对话标签 / 管理全部标签」。最后这个能在不翻片段的情况下清掉一个标签，并告诉你有多少条片段被影响。
- **筛选用椭圆短名，管理用全名**：筛选胶囊必须保持一行所以会省略（完整名字在 tooltip 里），而删除控件上的名字**一律完整显示**——读不出名字的删除按钮等于不能用。
- **写入失败一定看得见**：存储配额满或页面禁用本地存储时，浮条会说明，面板顶部常驻红色警告，直到某次写入成功为止。在此之前版本是**完全静默**的（界面说"已固定 1 条"，刷新后全部消失、控制台零报错）。
- **每会话一份**：固定按会话隔离（右栏本身就是会话级的），另给「全部」视图做跨会话复盘；分组标题用**会话真名**（读 Session 的 `title` 投影）并订阅投影变化，所以在宿主里改名这里会跟着变；还没有标题的新会话才退化为"最新一条固定片段的首行"。
- **原文顺序优先**：按**轮次**排序（`turn` 来自消息行，稳定且老数据也有），而不是你固定的时间顺序——你脑子里的地图是文章结构，不是操作历史。
- **"跳回未加载的历史"走 turnOutline**：点击一条不在已加载窗口里的片段时，用 `turnOutline` 投影把轮次换成 `turn/start` 的 seq，再 `session.loadThrough(seq)` 分页后重试定位。
- **正文保留换行**：固定时同时保存"原始文本（保留换行与缩进）"和"归一化文本"。前者用于显示与复制，后者只用于搜索、定位、去重——职责分开。**两者从同一次截断得出**，否则空白密集的选区上会指向不同的段落。代码片段用等宽字体单独排版。
- **动态高度但有上限**：折叠态 1-3 行自适应，用 `max-height` 而非 `line-clamp` 兜底（否则块级内容会漏出裁剪）；超过 600 字的选区按前 600 字固定，卡片上标「已截断」。
- **固定过的原文有持久标记**：优先用 CSS Custom Highlight API（不改 DOM），不支持时退化为本插件自己的 `<mark>`；标记只画当前会话。刷新是**增量的**——只有内容真的变了的消息行才重建索引，重算期间不断开 DOM 观察器，插件自己插的 `<mark>` 也会被识别、不再自激。
- **定位会校验，并挑最接近的那个**：同一段文字在一条消息里可能出现多次，所以每个候选位置都按记录偏移打分取最近的，且**解析出的文本必须与存储的引文一致**才采用——宁可退回"整条消息高亮"，也不标错地方。卡片上出现「原文未找到」就是这条没通过校验。
- **跳转以"那段文字"为中心**：一条消息里多个固定互不干扰，点哪段跳哪段；目标位置会被箝制在滚动范围内，所以末尾的片段自然停在底部。
- **锚点不存 DOM 位置**：标注靠 `消息 key（会话装配引擎的稳定 key）+ 引文 + 相对字符偏移`定位，遵循 W3C Web Annotation 的建议（绝对偏移在内容变化时必然漂移）。消息重新渲染、流式追加、历史分页都不会让固定失效。
- **不做 markdown 解析、不做 HTML 快照**：存的是"用户选的字符 + 固定当场看到的事实"（`block`/`lang`/`partial`）。对**渲染后**的文本跑 markdown 解析是"造结构"（正文里的 `-`、`1.`、`|` 会被变成列表、表格）；HTML 快照则会把宿主的主题变量与内部类名写进用户历史数据，平均 +139% 体积、最坏单条 15 倍。
- **跳转写滚动容器而不是 `scrollIntoView`**：应用框架是 `overflow:hidden`、对话自己拥有唯一滚动口，让浏览器挑滚动容器会落点错乱。
- **样式只用主题 token**（`--dsw-alias-*` / `--dsw-specific-sidebar-fill`），不 import 任何 Harness 客户端包，亮/暗主题都跟随宿主。
- **失败不静默**：固定、取消固定、打开面板、"标记找不到原文"都会在界面上显示，而不是只写控制台。

### 关于 markdown 格式的取舍

固定片段**不做** markdown 还原（不存 HTML 快照）：实测那样平均 +139% 存储、最坏单条 15 倍，还会把宿主的主题变量、类名、重复 `id`、可点击的「复制」按钮一起搬进用户数据。采用的做法是保留换行 + 记录 `block`（code/table/quote/list/prose）与代码语言，代码片段用等宽排版。表格在 268px 的侧栏里本来也放不下，损失可接受。

## 数据与边界

- 数据存在浏览器的 `localStorage`，键 `dsh-pins/v1`。换浏览器、清站点数据会丢；因为它属于"浏览器的视图状态"，与 Harness 自己保存右栏布局的方式一致。
- 固定一个还没加载进窗口的历史消息（分页往上、或已被上下文压缩）时，点击会提示先向上滚动加载历史，而不是默默跳错地方。
- 选区跨两条消息时不会固定（避免存下一个语义不明的区间）；跨段落但在同一条消息内是支持的。

## 双锚点这件事，最后是怎么收的

审计把它列为"唯一'宿主改一次就整体失效且无法自检'的风险"，要求建 `(msgSeq, partIndex, offset)` 与 DOM 锚并存。实际落地时拆成了两半，各用一种更便宜的方式解决：

1. **排序正确性**（原风险的一半）：`msgOrder` 曾是"固定那一刻加载窗口内的序号"，翻页后会错序。现在按**消息 key 维护高水位**（`stableOrderFor`）：一条消息的序号只增不减，窗口变大不会让两条记录的基准不一致。**这一半不再需要 `msgSeq`。**
2. **跳转的容错**（另一半）：跳转仍以 DOM key 为主锚（它精确、便宜），但新增**按位置回退**（`resolveRow`）：key 找不到时，改用固定的 `(turn, msgOrder)` 在同一轮已渲染的行里取第 N 条。它不依赖 key 的字符串格式，只在"那一轮确实已加载"时生效，所以不会跳错轮次。
3. **滚动容器的回退**也补上了：`findScroller()` 的启发式现在排除本插件自己的面板（否则 hover 展开后，面板列表的 scrollHeight 可能超过对话区，回退会去滚右栏）。

**没有做的**：从会话事件里重建 `msgSeq → 源码偏移`。审计自己的实测说约 21% 的选区映射不上，而它的收益只在"宿主把 `data-chat-*` 属性整批改名"那一天兑现。把 21% 的失败率和一套源码映射器，换一个更低概率场景的容错，不划算——**真到那天，位置回退已经保证了"降级可用"**（跳转仍然落在正确的轮次里，只是可能落回整条消息）。

**残余风险（如实记录）**：如果宿主同时改掉了 `data-chat-flow-key`、`data-chat-turn` 与 `[data-conversation-scroll]` 三者，固定标记与精确跳转会一起失效，届时需要按新契约重做锚点（数据本身不会丢，仍是可读的文本与轮次）。

## 「Host 工具」是什么意思

**先说结论：做了芯片引用之后，这件事已经降级为可选项。** 芯片的展开由客户端的 codec 在发送前完成，模型每收到一个芯片就拿到那段正文——**不需要任何工具参与**。工具剩下的唯一价值是"模型自己想主动读一遍全部固定片段"（例如你说"按我固定的那几条重新梳理"，而你没有逐个引用它们）。

要做的话是：给 Host 半边注册一个 **agent 工具**（例如 `pins_list` / `pins_read`），让模型能**主动**调用它读取当前会话的固定片段。`index.js` 里那个 `pinsHost` 服务就是为这件事预留的入口，**通道还没打通**。

几个已知的约束（决定了它比听起来麻烦）：

- **数据在浏览器**：固定片段存在右栏的 `localStorage`，Host 进程读不到。所以得先有一条"浏览器 → Host"的数据通路（面板把当前会话的固定片段同步给 Host，或 Host 按需向页面请求）。
- **只做显式调用**：审计明确否掉的是"自动把固定片段注入模型上下文"（那会消耗上下文、且用户看不见）。工具形态是**模型自己决定要不要读**，读了什么在会话记录里可见。
- **权限边界**：固定片段是你手选的内容，不是秘密，但它属于"用户数据"，所以工具的返回应当只覆盖**当前会话**，且不写入任何隐性状态。
