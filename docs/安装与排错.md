# 安装与排错

## 一条命令做了什么

```bash
dsh plugin --profile web add github:ylw-ux/dsh-pins-fixtool
```

`dsh plugin` 是 pnpm 的直通命令，但它比裸 pnpm 多做三件事（源码在 `@deepseek-ai/dsh-plugin-manager` 的 `operations.ts`，`runProfilePnpm`）：

1. **跑 pnpm 之前**做兼容性预检：读 spec 所指包的 `package.json`，检查它声明的 DSH peer 依赖是否满足。不满足就直接拒绝，**不下载、不执行任何构建脚本**，并打印出解除办法。
2. **pnpm 成功后对账（reconcile）**：把这次**新增**的依赖里声明了 `dsh.bundle` 的那些，追加进 profile `package.json` 的 `dsh.profile.bundles`——这就是"装完自动启用"。
3. 对账时若某个新依赖**没有**声明 `dsh.bundle`，只打印一句警告：

   ```
   dsh: warning: <name> declares no dsh.bundle — installed as a plain dependency, not a profile layer
   ```

   （它会被装进 `node_modules`，但不会成为 profile 的一层，也就不会加载。）

所以对 dsh-pins 这种声明了 `dsh.bundle.patch` 的包，**一条命令就装完并启用**，不需要再去界面里点"启用"。

## 三种 spec

| 形式 | 命令 | 适用 |
|---|---|---|
| GitHub | `dsh plugin --profile web add github:ylw-ux/dsh-pins-fixtool` | 公开发布后推荐 |
| npm | `dsh plugin --profile web add dsh-pins` | 发布到 npm 后 |
| 本地目录 | `dsh plugin --profile web add D:\path\to\dsh-pins` | 开发；建立的是 `link:` 依赖，改代码刷新页面即可生效 |

**git 形式的一个坑（dsh-pins 不受影响）**：从 git 安装的包会跑它的 `prepare` 脚本，而 pnpm 11+ 默认**拦截依赖的构建脚本**。dsh-pins 没有任何 `scripts`，所以不会触发；如果你在改这个包时加了构建步骤，就要按 pnpm 打印的包名在 profile 的 `pnpm-workspace.yaml` 里加 `allowBuilds`。

## profile 里被改动了什么

装完之后，`$DSH_HOME/profiles/web/` 下只有这些变化：

```
package.json          dependencies 多一条 "dsh-pins"
                      dsh.profile.bundles 多一个 "dsh-pins"
pnpm-lock.yaml        记录这次安装
node_modules/dsh-pins 指向包目录的链接（本地目录安装时是 junction）
```

它**不会**改 `cordis.patch.yml`——插件自己带 `cordis.patch.yml`，通过 bundle 机制插行。

## 排错

**装完界面里没反应**

1. 刷新浏览器（F5）。HMR 打开时配置变化会立即重载，但浏览器半边的模块不一定跟着换。
2. 还不行就重启 `dsh`。
3. 打开 DevTools 看控制台：注册成功会打印 `[dsh-pins] 已注册 @ 固定片段触发源`；失败会打印原因（例如 `输入触发器服务没有出现`）。

**报版本不兼容**

预检会打印确切的解除命令：

```bash
dsh plugin --profile web allow-version <包名>@<版本> --dsh-version <当前DSH版本> --accept-risk
```

dsh-pins 不声明 peer 依赖，正常情况下不会走到这一步。

**左栏入口有、面板打不开**

右栏的标签类型注册失败时，左栏入口的 tooltip 会写出原因。控制台里会有 `[dsh-pins] tab type registration failed`。常见原因是右栏服务尚未就绪——插件会重试 10 秒。

**固定片段突然全没了**

先确认是不是换了浏览器 profile 或清了站点数据——数据只存在 `localStorage` 的 `dsh-pins/v1` 键里，没有服务端副本。面板顶部出现红色警告表示**写入失败**（配额满或页面禁用了本地存储），此时界面里的条数仍然是内存里的，刷新就会丢。

**想把插件目录挪个地方**

小心：profile 里记录的是 **`link:` 绝对路径**，移动目录会让链接悬空。

```bash
# 正确做法：移动之后重新 add 一次新路径
dsh plugin --profile web remove dsh-pins
dsh plugin --profile web add D:\新路径\dsh-pins
```

手改 junction 而不更新 profile 的 `package.json` 是不行的：下一次任何 pnpm 操作都会按记录里的旧路径重建链接。

## 卸载

```bash
dsh plugin --profile web remove dsh-pins
```

只会移除依赖与 bundle 选择。**浏览器里的固定片段不会因此删除**——要清掉的话在 DevTools 里删 `dsh-pins/*` 那几个键。
